# The Library — TMoC Books

Static reading site for the community's book translations.

- Live site: https://TMoC-89.github.io/tmoc-books/
- Deployment: GitHub Pages, via `.github/workflows/pages.yml`, from `main`
- Local preview: `python3 -m http.server 8000`, then open http://localhost:8000/

The built site is committed, so GitHub Pages serves the repository as it is. There are no runtime
dependencies, and the build tool needs only Python 3.9+ (standard library).

## How the site is put together

```
index.html                     collection page        (generated)
library.json                   catalogue: shelves, cards, series, site metadata
search/                        search page + index    (generated)
404.html                       not-found page         (generated)
assets/
  base.css                     colours, type, buttons — shared by every page
  library.css, library.js      collection, series, search and 404 pages
  reader.css, reader.js        the book reader (all books)
  reviewer.css, reviewer.js    Reviewer Mode, loaded only when someone opens it
<book>/
  book.json                    the reader's settings: titles, languages, contents, downloads, reviewer
  index.html                   generated page; the book text sits between the BOOK-CONTENT markers
  *.md                         Markdown downloads
materialist-tendencies/        series landing page (generated) + volume-1 … volume-4 readers
glossarium/source-de.html      German source text, fetched only by Reviewer Mode
tools/build.py                 rebuilds every page and the search index
tools/search_index.py          search index builder (used by build.py)
```

Each reader page has two parts. The **book text** (the `language-view` blocks with their
`book-section`s) is the source and lives in `<book>/index.html` between
`<!-- BOOK-CONTENT:START -->` and `<!-- BOOK-CONTENT:END -->`. **Everything around it** — head, top
bar, sidebar, cover, chapter pagers, footer — is generated by `tools/build.py` from `book.json`
and `library.json`. Edit the text between the markers or the JSON files, never the generated parts.

## Everyday tasks

| Task | What to do |
| --- | --- |
| Fix a typo in a book | Edit the text between the markers in `<book>/index.html` (and the Markdown download), then run `python3 tools/build.py` |
| Change a title, subtitle, contents entry or download | Edit `<book>/book.json`, then build |
| Change a card, shelf or description on the collection page | Edit `library.json`, then build |
| Change the design | Edit `assets/*.css` / `assets/*.js`, then build (asset URLs carry a content hash) |
| Check without writing | `python3 tools/build.py --check` — validates every book and fails if pages are out of date |

`python3 tools/build.py --pages` skips the search index when you only changed layout.
The build is deterministic: running it twice changes nothing the second time. CI runs `--check` on
every push and pull request, and deployment waits for it.

## Adding a book

1. Create `<slug>/` with the Markdown downloads.
2. Create `<slug>/index.html` containing only the book text between the markers:
   ```html
   <!-- BOOK-CONTENT:START -->
   <div class="language-view" data-lang="en">
     <section class="book-section" id="en-intro" data-key="intro" data-title="Introduction">…</section>
     …
   </div>
   <div class="language-view" data-lang="fr">…same data-key values…</div>
   <!-- BOOK-CONTENT:END -->
   ```
   Give paragraphs stable ids (`passage-en-00001` …): search results and Reviewer Mode link to them.
   Use the same `data-key` for matching sections in each language so the language switch keeps the
   reader in the same chapter. Endnote references are `<sup><a href="#note-id">1</a></sup>`; the reader
   shows the note in a popover.
3. Create `<slug>/book.json` (copy one of the existing ones). Fields:
   - `searchId` — next free number (search results link to books by this id)
   - `slug`, `path`, `pageTitle`, `description`
   - `languages` (`["en"]`, `["en", "ar"]` or `["en", "fr"]`), `langKey` (browser storage key for the language choice)
   - `title`, `subtitle`, `author`, `edition` — one value per language; optional `kicker`
   - `downloads` — Markdown file per language
   - `home` — the sidebar's back link
   - `review` — Reviewer Mode settings; keep `version` unchanged once reviewers have started, because
     drafts are stored under it
   - `nav` — the contents, per language: `{ "id": "en-intro", "title": "Introduction", "level": 1 }`,
     with `level` 2 or 3 for nested entries and an optional short `label`
4. Add the book to `library.json` (`books`), then run `python3 tools/build.py` and commit everything.
   For a French original on a catalogue card, set `originalTitle` to
   `{ "lang": "fr", "text": "Original title" }`. Existing `arabicTitle` values remain supported.

### The City of Isis

Pierre Rossi’s *The City of Isis / La Cité d’Isis* is in `the-city-of-isis/`, with the full English
translation and French original. Both Markdown downloads are byte-for-byte copies of the supplied
final pair. The reader includes the title pages, English translator’s note, preface, ten chapters,
printed contents and colophon, and twelve linked footnotes in each language.

To reimport a revised final pair, run `python3 tools/import_city_of_isis.py /path/to/pair`, then
`python3 tools/build.py`. The importer handles this pair’s Markdown syntax using only the Python
standard library. Reimporting replaces this book’s content and metadata; keep its review version
stable once reviews have started unless the underlying edition has intentionally changed.

## Reader features

- Contents sidebar with nested chapters, the current position highlighted and kept in view
- English ⇄ Arabic or French switch that keeps the reader in the same chapter (and follows original-language chapter links)
- Note previews: tapping a note number shows the note in place, with a link to the full notes
- Text size and theme (auto / light / dark), remembered per browser
- Reading position saved per book: “Continue” on the book's cover and on the collection page
- Arriving from search: lands on the passage, highlights the words, links back to the results
- Reviewer Mode: English beside the source text; mark passages, propose wording, export a JSON review
- Books are laid out in full when they load, so taps respond immediately afterwards. Reviewer Mode
  builds its passage cards section by section as you scroll
- `?perf=1` on any book shows a small panel timing each tap, with a "Copy report" button (`?perf=0` turns it off)

## Search

`search/data` is generated by the build: `manifest.json`, `terms/*.json` (terms → passage ids) and
`passages/*.json` (the text). A query loads only the term files it needs, counts matches per work,
and fetches text just for the excerpts on screen. French originals are searchable and have their own
language filter; accents are normalized when matching. Arabic matching ignores vowel marks, letter
variants (أ إ آ → ا, ة → ه, ى → ي) and common prefixes (ال، و، ب، ل…). Phrases in “quotation marks”
are checked against the text. Search URLs look like `search/?q=Marx&work=3&lang=en`.
